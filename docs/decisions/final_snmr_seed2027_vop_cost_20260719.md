## 0. 전사 상태 + QC

- 시트 10,000행 중 0.4–0.7V = 8,000행 전사 완료, 0.8V = 2,000행 미전사.
- **초기 실행에서 전사 오타 22셀 발견 → 사용자가 원본 대조 후 전부 수정
  (2026-07-19).** (파싱 불가 3건: `13.6.69`/`15.73.`/`133..33`; 자릿수 slip
  19건: avg 폭주 11 + std 폭주 8, 예 TT-557 0.7V avg=157082.) 스크립트의
  QC(파싱 불가 + avg∉[-50,300]mV / std∉[3,30]mV)는 재발 방지용으로 유지.
- **수정 후 재실행 기준: 아웃라이어 0건, 8,000행 전부 유효.** avg 범위
  -0.44~218.58 mV, std 범위 9.41~17.81 mV (모두 물리적으로 타당; avg 최대
  218.58 mV로 200 mV 초과하는 정상 slow 코너가 실재 → 상한 300 mV 유지).
  아래 수치는 이 clean 재실행(8,000행) 기준.

## 1. Part A — 원본 데이터 Vop 충분성 (GP 없이, 직접 비용 신호)

2,000 조건을 0.4–0.7V만으로 z(Vop)=6.50 교차 여부 판정:

| 분류 | 조건 수 | 비율 |
|---|---:|---:|
| RESOLVED (Vmin이 0.4–0.7V 안에서 확정) | 1,526 | 76.3% |
| LEFT-CENSORED (Vmin이 이미 0.4V 아래) | 306 | 15.3% |
| 0.7V보다 높은 Vop 필요 (미해결) | 168 | **8.4%** |

- **약 91.6%(RESOLVED+censored)는 0.8V 없이 이미 완전히 결정됨.**
- RESOLVED 중 0.7V 천장 20mV 이내는 47개(3.1%) — 0.8V가 있었다면
  값이 바뀔 여지가 가장 큰 후보군.
- 판정: 0.8V는 8.4% 조건에서만 추가 정보를 준다. 그 조건들이 수율
  스펙상 중요한 코너/꼬리에 있는지가 "0.8V 생략으로 비용을 더 줄일 수
  있는가"의 핵심 — 0.8V 전사 완료 후 재판정.

## 2. Part B — GP 대리모델 hold-out 정확도 (0.4–0.7V, noise-aware)

- 조건 단위 grouped split(15% hold-out), noise-aware(FixedNoise, n_mc=5000).
- **mu R²=0.9817 (RMSE 5.35mV), sigma R²=0.9845 (RMSE 0.221mV)**
- **Vmin RMSE(hold-out, censoring-aware) = 13.50mV** (231/300 조건 채점)
- lengthscale: **ell_pu/ell_cn = 1.083 (PG(cn) 우세)** — Stage A(1.08)/
  Stage B(1.14)의 PG≫PU 계층 재현. Vop lengthscale(5.17)이 가장 짧음
  = Vop 민감도 가장 큼(정상).
- Stage B 4D 실데이터(mu R²=0.9785)와 정합적 — 9D로 확장해도 정확도 유지.

## 2.5 [결론] Spec 관점 재검토 — Vop 0.4–0.7V로 충분 (2026-07-19)

> 스크립트: `scripts/final_snmr_seed2027_spec_review.py`,
> `scripts/final_snmr_seed2027_extrap_test.py`
> 결과: `results/final_snmr_seed2027/spec_review_0p7V.json`,
> `extrap_test_0p7_vs_0p8.json`

**공정 spec 맥락(공정 담당 확인):** nominal Vop=0.75V, on-chip/off-chip IR
drop 반영 시 **Vmin spec = T0 0.625V, EOL 0.675V**. 따라서 Vmin이 0.7~0.8V를
넘는 조건은 이미 spec을 크게 벗어난 fail이며 **정확한 Vmin 값이 불필요**
(fail로 분류되기만 하면 됨).

**핵심 근거 1 — 0.8V는 spec 판정에 수학적으로 무관.**
spec 전압 0.625·0.675V가 모두 **[0.6, 0.7] 구간 내부**이므로 z(V_spec)은
0.6V·0.7V 두 점만으로 선형 내삽된다. 실측 확인:

| spec | 0.4–0.7V 그리드 vs 0.4–0.8V 그리드 pass/fail 일치 | max\|Δz\| |
|---|---|---|
| T0 (0.625V) | **2000/2000 (100%)** | **0.00e+00** |
| EOL (0.675V) | **2000/2000 (100%)** | **0.00e+00** |

Δz가 정확히 0 — 경험적 근사가 아니라 구조적으로 0.8V가 개입할 수 없음.

**핵심 근거 2 — 0.4–0.7V 학습 GP가 spec 판정을 재현.** (hold-out 300 조건)

| spec | pass/fail 일치율 | 오분류 내역 | z-margin RMSE |
|---|---|---|---|
| T0 (0.625V) | 295/300 (**98.3%**) | FP=4, FN=1 | 0.573 |
| EOL (0.675V) | 298/300 (**99.3%**) | FP=1, FN=1 | 0.322 |

(Z_t=6.5 대비 z RMSE 0.32–0.57 = 5~9%.)

**핵심 근거 3 — spec 영역 Vmin 정확도도 동등.** 0.4–0.7V 학습 GP의
Vmin RMSE: spec 영역(Vmin≤0.7V, n=1526) **9.14mV**, out-of-spec
(0.7–0.8V, n=90) 20.77mV(관심 밖이며 그마저도 90/90 외삽 성공).
0.8V 추가 학습 시 mu R² 0.9817→0.9834로 사실상 불변.

**모집단 분포(n=2000):** PASS T0 1624(81.2%), PASS EOL 1771(88.5%),
FAIL EOL 229(11.4% — 관심 밖).

### 판정
**Vop 0.4–0.7V 4레벨로 확정. 0.8V 시뮬레이션·전사 생략(이 metric 예산 20% 절감).**

- 0.7V가 **최소 상한**임에 주의: EOL spec 0.675V를 bracket하려면 0.7V가
  반드시 필요(0.6V 상한이면 0.675V가 외삽이 되어 불가). 즉 0.4–0.7V는
  "줄일 수 있는 최대치"이자 "spec이 요구하는 최소치".
- 남은 리스크: T0에서 FP=4(1.3%, 낙관적 오분류)가 유일한 주의점. 단 이는
  **0.8V 생략 탓이 아니라 대리모델 자체의 오차**(spec 전압이 0.8V를 쓰지
  않으므로). 개선하려면 Vop 레벨이 아니라 조건 수·corner anchor로 접근.
- **이 판정은 spec(0.625/0.675V)에 종속**됨. 향후 IR drop budget이 완화되어
  spec이 0.7V를 넘어가면 0.4–0.7V 데이터로는 지원 불가 — 재검토 필요.
- **Vtrip에도 동일 논리 적용 가능**: spec 전압이 동일하게 [0.6,0.7] 내부이고,
  Vtrip은 SNMR보다 단조성이 뚜렷해 내삽이 더 안정적. 다만 Vtrip 시트 전사 후
  같은 두 스크립트로 한 번 확인할 것(구조적 논거는 동일하나 실측 확인 권장).

### 논문 표현 방안 — 우측 censoring
논문에는 이미 **좌측 censoring**(Vmin이 표본 전압 범위 아래)이 있다. 이번
건은 그 대칭인 **우측 censoring**으로 기술하는 것이 가장 깔끔하다:

> Vop 범위는 데이터 가용성이 아니라 **spec이 결정**한다. 표본 범위를
> [0.4, 0.7]V로 잡은 것은 이것이 T0(0.625V)·EOL(0.675V) spec을 bracket하는
> 최소 구간이기 때문이다. 이 범위 밖의 조건은 양쪽 모두 censoring으로
> 처리한다 — 아래쪽은 "Vmin < 0.4V"(이미 충분히 안전), 위쪽은
> "Vmin > 0.7V"(이미 spec 위반). 두 경우 모두 **정확한 값이 의사결정에
> 기여하지 않으므로** 연속 오차 지표에서 제외하고 분류 결과만 사용한다.

이 프레이밍의 장점: "데이터가 없어서 자른다"가 아니라 "**의사결정에 필요한
구간만 시뮬레이션한다**"는 능동적 실험설계 논거가 되며, 논문의 비용 절감
서사(§1.2–1.3, §5.5 예산-정확도)와 직접 연결된다.

## 3. (참고) 0.8V 포함 전체 실행 결과

동일 스크립트 재실행 → `metrics_maxVop0.8.json` 생성 → "Compare" 섹션이
0.7V baseline과 자동 diff (mu R², Vmin RMSE, pct_needs_higher_vop 변화).

**비교로 확인할 것:**
1. Part A의 8.4%(168 조건)가 0.8V에서 실제로 해결되는가, 아니면 그것도
   0.8V를 넘겨 여전히 미해결(→ Vop 범위 자체가 부족)인가.
2. Part B의 Vmin RMSE가 0.8V 추가로 유의하게 좋아지는가. 거의 안 변하면
   → **0.8V 시뮬레이션 생략이 정당화**(추가 비용 절감 여지). 크게 좋아지면
   → 0.8V는 필요(특히 저-Vmin/고-SNMR 코너 정확도에).
3. 좌측 판단은 Stage-4에서 Vop=0.9 생략을 정당화했던 것과 같은 논리
   (crossing이 범위 안에서 100% 일어나면 그 위 레벨은 불필요).
